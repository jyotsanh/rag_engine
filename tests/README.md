# Test conventions

## Layout
- `tests/unit/` — no network, no containers. HTTP mocked with `respx`, infra replaced by fakes.
- `tests/integration/` — real MongoDB / Redis / Qdrant via testcontainers, real Celery worker, local fixture website.
- `tests/browser/` — real headless Chromium via Playwright against the fixture website. One-time setup: `uv run playwright install chromium`.
- `tests/container/` — builds the Docker images (`Dockerfile`) and runs them against the fixture website (host network). Opt-in.
- `tests/fixtures/site/` — the static fixture website served by a local server fixture. Binary documents are generated by `uv run python tests/fixtures/build_documents.py` (outputs committed).

## Markers
| Marker | Meaning |
|---|---|
| `unit` | Fast, isolated (default path) |
| `integration` | Needs containers / Celery worker |
| `browser` | Needs Playwright Chromium |
| `container` | Builds/runs the Docker images (minutes). Skipped unless `--run-container` |
| `live` | Hits real external services (OpenAI, public websites). Never run by default |
| `eval` | Retrieval quality evaluation |

`unit` / `integration` / `browser` / `container` are applied automatically from the
directory. `live` tests are skipped unless `--run-live` is passed, `container` tests unless
`--run-container`. Integration tests are skipped (not failed)
when no Docker daemon is reachable, browser tests when Chromium cannot be launched.

```bash
uv run pytest -q -m "not integration and not browser"   # fast path (no Docker)
uv run pytest -q -m integration                          # starts containers once per session
uv run pytest -q -m browser                              # headless Chromium
uv run pytest -q --run-container -m container            # builds + runs the worker image
uv run pytest -q --run-live -m live                      # real OpenAI / public sites
```

Every test has a 120 s timeout (`pytest-timeout`), so a hang fails the stuck test by name.

## Fixtures
| Fixture | Scope | Purpose |
|---|---|---|
| `override_settings(**fields)` | function | Validated patch of the global `settings` singleton, auto-restored |
| `mongo_service` / `redis_service` / `qdrant_service` | session | testcontainers with auth, same images as `docker-compose.yml` (`tests/support/services.py`) |
| `fixture_site` | function (server is session) | Local edge-case website on a free loopback port; request log + `/flaky` reset per test. `SITE_PAGES` maps each URL to its expected crawl outcome (`tests/support/fixture_site.py`) |
| `integration_settings` | function | Points `settings` at the containers. Unique `MONGO_DB` per test; Mongo DB dropped, Redis DBs flushed and Qdrant collections deleted on teardown |

## Naming
- One plain pytest class per plan step: `Test<PascalCaseFeature>_S<step>` (e.g. `TestUrlNormalization_S23`).
- Class docstring names the step: `"""S23 — URL normalization: <what is under test>."""`
- **Not** `unittest.TestCase`: bare `assert`, methods take fixtures as parameters.
- Method names: `test_<subject>_<expected_behavior>`.
- A section banner sits above the test classes:
  ```python
  # ---- #
  # Tests
  # ---- #
  ```
- Test-only helper subclasses/models live at module level and are underscore-prefixed (`_FakeEmbedder`) so pytest does not collect them.
- Arrange / Act / Assert separated by blank lines; add `# Arrange` / `# Act` / `# Assert` comments when the flow is not obvious.

## Checks before handing back a step
```bash
uv run ruff check . && uv run ruff format --check . && uv run ty check && uv run pytest -q
```
